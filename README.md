# The Norns III

The placement experiment of Yggdrasil III: does seeding VPR's simulated anneal from netlist
clusters (Loki III L2) or from the provenance hierarchy (Odin III) improve placement, and how
hot can the anneal start before it destroys the seed?

- `docs/plan/norns-experiment.md` — the experiment design (seeds, injection, the crossover
  sweep, the checkpointing arm, metrics).
- `docs/plan/vtr-interfaces.md` — the pinned VTR interfaces, verified (seeding, schedule,
  checkpointing) with the source locations.
- `docs/plan/EXPERIMENT.md` — the measured results (generated by `scripts/report.py`).
- `docs/paper/` — the paper (`norns.tex`, IEEEtran, Overleaf-uploadable), updated as runs land. Its
  Methodology holds the seed-construction detail (`Seed construction in detail`) and the
  benchmark table (`Benchmarks`, sizes in `data/benchmark-sizes.json`).
- `docs/index.md` — the index of the documentation.
- `patches/` — the VTR patch-set; empty of changes, because the pinned build already provides
  the checkpointing the experiment needs.

Urd uses what the design was (the provenance hierarchy), Verdandi what is recovered now
(Loki III clusters), and Skuld what shall be (the placement they constrain).

## Running it

    . scripts/env.sh                     # from the checkout; paths default to $WS_ROOT (~/odin3-ws),
                                         # override ODIN3_ROOT, VTR_ROOT, LOKI_HOME, NR_PY, NORNS_LOCK
    scripts/run_design.sh ch_intrinsics  # front end, baseline, Loki clusters, seeds, matrix
    scripts/matrix.py checkpoint <design> # the --place_checkpointing off control sweep
    scripts/report.py                    # regenerate docs/plan/EXPERIMENT.md
    scripts/fill_paper.py                # regenerate docs/plan/paper-numbers.tex

Round two (bitwise seeds, N1/N2). Steps 1 to 5 need the local `runs/` tree (Odin III, Loki and VPR
outputs; not committed; `round2.py` and `matrix.py` write the run records straight into `data/`). Steps 6 to 9
read only the committed `data/` and regenerate every document byte-identically from a fresh checkout:

    1. scripts/build_words.py            # word membership per design (reruns the Odin III script)
    2. scripts/build_word_seeds.py       # the round-two seed files (words, slices, hier, words_partial, ...)
    3. scripts/round2.py soft|chunk stage2 [design ...]   # the VPR runs (heavy lock, one at a time)
    4. scripts/round2.py freeze          # record the best new family (data/analysis/best.json)
    5. scripts/structure.py all|graph|partial   # N1, N2 and the seeded share -> data/analysis/*.json
    6. scripts/report.py                 # docs/plan/EXPERIMENT.md
    7. scripts/fill_paper.py             # docs/plan/paper-numbers.tex, paper-summary.json
    8. scripts/write_paper_prose.py      # fills docs/paper/norns.tex from the numbers
    9. scripts/write_round2.py           # docs/paper/r2-*.tex (the round-two sections and appendix)

Round three (the Norns packer, I/O words, packing experiments, proximity). The protocol with every numeric rule is
`docs/plan/round3.md` (committed before any round-three run). Steps 1 to 7 need the local `runs/` tree; steps
8 to 11 read only the committed `data/` and regenerate byte-identically:

    1. scripts/n8.py                     # RQ-N8: purity, split factor, null, coverage-loss split (no VPR)
    2. scripts/io_words.py               # RQ-N10: io-words and their LUT coverage (no VPR)
    3. sh packer/build.sh                # the Norns packer: private VTR tree at packer/VTR_COMMIT + overlay -> $NORNS_VPR
                                         # (heavy lock; sh packer/diffstat.sh refreshes packer/DIFFSTAT.txt)
    4. scripts/round3.py gate            # control gate: stock vs Norns .net, 15 designs (data/analysis/r3-gate.json)
    5. scripts/round3.py pilot; grid     # beta pilot on the 4 smallest designs, then freeze the grid
    6. scripts/round3.py chunk arms      # Stage-4 runs (heavy lock per design; 3 VPR seeds); `status` shows progress
    7. scripts/n11.py                    # RQ-N11 on the stock analytic runs -> data/<d>/n11.json, data/analysis/n11*
    8. scripts/r3stats.py                # every round-three statistic and status -> data/analysis/r3-results.json
    9. scripts/write_round3.py           # docs/paper/r3-*.tex (sections and appendix)
   10. scripts/report.py                 # docs/plan/EXPERIMENT.md (includes the round-three tables)
   11. tectonic -X compile docs/paper/norns.tex --outdir <dir>   # copy norns.pdf to docs/paper/build/

Fix round (2026-10-25, after review; protocol entry in `docs/plan/round3.md`): `scripts/r3fix.py ident|stockn|timing|gate2|match`
(pack-only style, no routing, heavy lock; results `data/analysis/r3fix-*.json`) need `runs/`; `scripts/n11.py` was rerun, then steps 8 to 11.

The Loki analysis venv (numpy, scipy, scikit-learn, networkx, cffi) is built per the Loki
CLAUDE.md and kept outside the Loki checkout; Loki is imported from its checkout through
`PYTHONPATH`, never installed into or edited. Every VPR run takes the heavy lock
`$NORNS_LOCK` (default `/tmp/claude-1000/odin3-heavy.lock`), one at a time, smallest design first.

## Limitations of the Norns packer (measured 2026-10-25, not fixed)

The proposal step (up to 30 unclustered members of a cluster's dominant group handed to the candidate queue) counts molecules
handed over, not molecules the queue accepted, and scans the group from the lowest atom id (netlist-order bias). A log-only counter
(packing unchanged: `.net` byte-identical to the previous binary on 45 of 45 headline configurations) gives, over the 15 designs,
medians of the queued share of handed-over molecules 49% / 46% / 48% and of proposal calls that queued nothing 13% / 55% / 49%
(module / word / word+io). Per design (queued share / calls with nothing queued; headline beta 4, seed 1):

| design | module | word | word+io |
|---|---|---|---|
| blob_merge | 92% / 0% | 5% / 99% | 13% / 97% |
| boundtop | 44% / 16% | 63% / 49% | 64% / 48% |
| ch_intrinsics | 82% / 1% | 87% / 20% | 87% / 20% |
| diffeq1 | 53% / 7% | 59% / 28% | 59% / 28% |
| diffeq2 | 63% / 6% | 75% / 20% | 75% / 22% |
| mkDelayWorker32B | 8% / 60% | 0% / 100% | 0% / 100% |
| mkPktMerge | 22% / 58% | 24% / 57% | 24% / 57% |
| mkSMAdapter4B | 22% / 20% | 50% / 55% | 48% / 47% |
| or1200 | 29% / 22% | 46% / 52% | 42% / 49% |
| raygentop | 49% / 13% | 43% / 60% | 38% / 60% |
| sha | 88% / 4% | 46% / 62% | 48% / 57% |
| stereovision0 | 80% / 7% | 78% / 68% | 78% / 68% |
| stereovision1 | 34% / 41% | 78% / 44% | 76% / 44% |
| stereovision2 | 17% / 57% | 46% / 37% | 46% / 37% |
| stereovision3 | 66% / 5% | 12% / 84% | 12% / 84% |

The fix (count queued molecules only, return a bool, scan order) is queued for round 4. Affinity-file entries that did not match
an atom are listed per design and source in `data/analysis/r3fix-match.json` (for example mkDelayWorker32B matches 38 of 1620 word entries).

Part of [Yggdrasil III](https://github.com/drpaj12/YggdrasilIII) (hub documentation:
<https://drpaj12.github.io/YggdrasilIII/>; this repository is a submodule under `components/`, and
the hub's [getting-started page](https://drpaj12.github.io/YggdrasilIII/getting-started.html) sets up
the tools it needs). Uses [Odin III](https://github.com/drpaj12/odin3) (manual:
<https://drpaj12.github.io/odin3/>), [Loki III](https://github.com/drpaj12/loki) (manual:
<https://drpaj12.github.io/loki/>) and [Wyrd III](https://github.com/drpaj12/wyrd) (manual:
<https://drpaj12.github.io/wyrd/>) to run the matrix.

Round four (packing census, knowns, hierarchy, arms with CPD; protocol docs/plan/round4.md; needs odin3 >= 0b90fff9 for the
attribution library, imported by scripts/timing4.py). Run with `. scripts/env.sh` and `$NR_PY` (scipy, networkx):

    sh packer/build.sh                       # rebuild the Norns packer (census, proposal-count option)
    $NR_PY scripts/round4.py join            # affinity join check -> data/analysis/r4-join.json (writes runs/<d>/r4/affinity)
    $NR_PY scripts/round4.py gate            # Stage-1 gates -> data/analysis/r4-gate.json
    $NR_PY scripts/round4.py census          # 45 census runs (stock, r3, r4 packings)
    $NR_PY scripts/round4.py arms 2b         # routed analytic arms with the timing report and attribution
    $NR_PY scripts/round4.py arms 5          # word-seed and stage x bit (scripts/r4stage.py) arms
    $NR_PY scripts/r4census.py; $NR_PY scripts/r4near.py; $NR_PY scripts/r4hier.py; $NR_PY scripts/r4depth.py
    $NR_PY scripts/r4stats.py                # data/analysis/r4-results.json
    $NR_PY scripts/write_round4.py           # docs/paper/r4-*.tex (byte-identical from committed data/analysis, data/<d>)

Packer options: `--norns_pack_census FILE`, `--norns_proposal_count queued|attempted`.
