# The Norns III

The placement experiment of Yggdrasil III: does seeding VPR's simulated anneal from netlist
clusters (Loki III L2) or from the provenance hierarchy (Odin III) improve placement, and how
hot can the anneal start before it destroys the seed?

- `docs/plan/norns-experiment.md` — the experiment design (seeds, injection, the crossover
  sweep, the checkpointing arm, metrics).
- `docs/plan/vtr-interfaces.md` — the pinned VTR interfaces, verified (seeding, schedule,
  checkpointing) with the source locations.
- `docs/plan/EXPERIMENT.md` — the measured results (generated by `scripts/report.py`).
- `docs/paper/` — the paper (IEEEtran, Overleaf-uploadable), updated as runs land.
- `patches/` — the VTR patch-set; empty of changes, because the pinned build already provides
  the checkpointing the experiment needs.

Urd uses what the design was (the provenance hierarchy), Verdandi what is recovered now
(Loki III clusters), and Skuld what shall be (the placement they constrain).

## Running it

    scripts/env.sh                       # paths; NR_PY is the Loki analysis venv
    scripts/run_design.sh ch_intrinsics  # front end, baseline, Loki clusters, seeds, matrix
    scripts/matrix.py checkpoint <design> # the --place_checkpointing off control sweep
    scripts/report.py                    # regenerate docs/plan/EXPERIMENT.md
    scripts/fill_paper.py                # regenerate docs/plan/paper-numbers.tex

The Loki analysis venv (numpy, scipy, scikit-learn, networkx, cffi) is built per the Loki
CLAUDE.md and kept outside the Loki checkout; Loki is imported from its checkout through
`PYTHONPATH`, never installed into or edited. Every VPR run takes the heavy lock
`/tmp/claude-1000/odin3-heavy.lock`, one at a time, smallest design first.

Part of [Yggdrasil III](https://github.com/drpaj12/YggdrasilIII). Uses
[Odin III](https://github.com/drpaj12/odin3) and [Loki III](https://github.com/drpaj12/loki).
